# Flaky tests and agents

## 1. A red test can send an agent toward the wrong fix

When a test is known to be flaky, quarantine it while it is fixed. Give it an owner and a date.

A flaky test fails sometimes without any code change. An agent that sees a red test tries to fix the code, even when the test is flaky. That creates a problem for engineers: the agent responds to the failure, but the failure can occur with unchanged code.

# Flaky tests and agents

## Recognize the failure and measure it

A flaky test fails sometimes without any code change. When an agent sees a red test, it tries to fix the code, even when the test is flaky. For engineers working with agents, this makes flakiness a problem to measure before directing a repair.

Start by rerunning each test 20 times on the same commit and counting its failures. Use the audit script:

```sh
scripts/flake-scan.mjs --runs 20 --json
```

Keep the commit the same throughout the measurement. The question is specific: how many times does each test fail across those 20 runs? Record the failure count for each test, so the measurement describes that test’s results across the full set of runs.

Agents tend to rerun until green or weaken the assertion. When reviewing an agent’s response to a failure, look for those actions. A green result after repeated attempts is one result within the sequence; the failure count preserves the rest. A weakened assertion changes what the test requires. Keep those actions distinct from measuring how often the test fails without a code change.

## Quarantine a known-flaky test while it is fixed

A required gate is a check that must pass. When it sometimes fails, it teaches agents and people to ignore it. A flaky test in that gate therefore affects how both respond to its failures.

Quarantine means moving a known-flaky test out of the required gate while it is fixed, with an owner and a date. Apply it to a test already known to be flaky. Keep the work explicit:

1. Move the known-flaky test out of the required gate.
2. Assign an owner.
3. Set a date.
4. Fix the test while it is quarantined.

The owner and date are part of quarantine. Include both when describing the work, alongside the test that needs fixing. This gives the engineer and agent a concrete task to follow instead of another attempt to rerun until green.

For lesson auditors: the rubric is the author’s own; it does not come from a vendor.
