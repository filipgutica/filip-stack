# release-notes

## What it does

`release-notes` drafts release notes from merged PRs between two tags. It groups PRs by Conventional Commit type, with features, fixes, and breaking changes first.

## When to use it

Use it when you need a release notes draft for a tag range. The skill runs only when you invoke it:

```text
/release-notes <from-tag> <to-tag>
```

Use `technical-writing` to edit prose. `release-notes` gathers the PRs and drafts the notes.

## How it works

1. Checks that `gh` is signed in. If `gh auth status` fails, it stops.
2. Checks that both tags exist. If either tag is missing, it stops before drafting with `TAG_UNRESOLVED`.
3. Gathers merged PRs between the tags and skips PRs labeled `skip-notes`.
4. Groups the PRs by type. For PRs with multiple type labels, grouping uses a strict-majority rule. Label order breaks ties.
5. Includes a migration line for each breaking change. If the PR body has none, the draft marks it `TODO: migration`.

## What you get

The skill writes `RELEASE_NOTES.md` in the working tree and stops. It never publishes.

The draft includes grouped release notes and marks missing migration guidance for breaking changes.
