# release-notes

## What it does

`release-notes` drafts release notes from pull requests merged between two tags.

## When to use it

Use it to prepare a release draft from merged PRs. For prose edits, use `technical-writing`.

This skill runs only when you invoke it manually:

```text
/release-notes <from-tag> <to-tag>
```

For example, with illustrative tags:

```text
/release-notes v1.0.0 v1.1.0
```

## How it works

You must be signed in to `gh`. The skill stops if `gh auth status` fails. Both tags must exist; if either is missing, it stops before drafting.

The skill gathers merged PRs, skips those labeled `skip-notes`, and groups the rest by Conventional Commit type. Features, fixes, and breaking changes come first.

If a PR has labels for multiple types, it goes in the group named by most of its labels. Ties follow label order.

Every breaking change needs a migration line. If the PR body has none, the draft marks it `TODO: migration`.

## What you get

The skill writes `RELEASE_NOTES.md` in your working tree and stops. It never publishes.

# release-notes

## What it does

`release-notes` drafts release notes from merged PRs between two tags. It groups PRs by Conventional Commit type, with features, fixes, and breaking changes first.

## When to use it

Use it to gather merged PRs and create a release-notes draft. Use `technical-writing` to edit the prose.

The skill runs only when you invoke it manually:

```text
/release-notes <from-tag> <to-tag>
```

You must be signed in to `gh`, and both tags must exist.

## How it works

1. Checks `gh auth status`. If the check fails, it stops.
2. Resolves both tags. If either tag does not exist, it stops before drafting with `TAG_UNRESOLVED`.
3. Fetches merged PRs between the tags, with a limit of 500.
4. Skips PRs labeled `skip-notes` and groups the rest by type.
5. Checks breaking changes for a migration line. If the PR body has none, the draft marks it `TODO: migration`.

For PRs with multiple type labels, grouping uses a strict-majority rule. The code breaks ties by label order.

## What you get

A `RELEASE_NOTES.md` draft in your working tree, with missing migration lines marked for completion. The skill stops after writing the file. It never publishes.
