# Flaky tests and agents

## 1. What a red test teaches

An agent that sees a red test tries to fix the code. It does this even when the test is flaky: a test that sometimes fails without any code change. The lesson starts with that mismatch. The agent responds to the failure as something to fix in the code, while the test can fail with the code unchanged.

Agents tend to respond in two ways: rerun until the test turns green, or weaken the assertion. Neither response is what this lesson means by fixing a known-flaky test. Rerunning until green leaves the test’s sometimes-failing behavior unresolved. Weakening the assertion changes what the test requires.

The problem also reaches beyond the agent’s response to one failure. A required gate that sometimes fails teaches agents and people to ignore it. Keeping a known-flaky test in that gate therefore carries a cost: the gate itself becomes something they learn to disregard.

For this lesson, keep the distinction clear: fixing code in response to red is different from fixing a test that fails without a code change.

## 2. Measure flakiness, then quarantine with ownership

Measure flakiness by rerunning each test 20 times on the same commit and counting its failures. Keep the commit the same throughout those runs. The exercise is to count failures across the 20 runs, rather than stop as soon as a rerun turns green.

Use the audit script:

```sh
scripts/flake-scan.mjs --runs 20 --json
```

The measurement asks a specific question: how many times did each test fail in 20 runs on this commit? Keep that question separate from the agent’s tendency to rerun until green.

For a known-flaky test, quarantine means moving it out of the required gate while it is fixed. Quarantine includes an owner and a date. Moving the test is only part of that definition; the owner and date belong with it.

Use those terms precisely when discussing the work: measurement counts failures, and quarantine moves a known-flaky test out of the required gate while it is fixed, with an owner and a date.
