# release-notes

## What it does

Drafts release notes from merged PRs between two tags. It groups PRs by Conventional Commit type, with features, fixes, and breaking changes first.

## When to use it

Use `release-notes` to gather merged PRs and create a release-note draft. Use `technical-writing` to edit prose.

Run it manually:

```text
/release-notes <from-tag> <to-tag>
```

Both tags must exist, and `gh` must be signed in.

## How it works

1. Checks authentication with `gh auth status`. If the check fails, it stops.
2. Resolves both tags with `git rev-list -n1 <tag>`. If either tag does not exist, it stops before drafting with `TAG_UNRESOLVED`.
3. Fetches merged PRs between the tags and skips PRs labeled `skip-notes`.
4. Groups PRs by type. For PRs with multiple type labels, it counts labels using a strict-majority rule. The code breaks ties by label order.
5. Checks breaking changes for a migration line. If the PR body has none, it marks the draft `TODO: migration`.

## What you get

A `RELEASE_NOTES.md` file in the working tree, with missing migration instructions marked for completion.

The skill never publishes. It writes the draft and stops.
