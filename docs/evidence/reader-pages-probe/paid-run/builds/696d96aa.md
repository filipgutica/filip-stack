# release-notes

## What it does

`release-notes` drafts release notes from merged PRs between two tags. It gathers the PRs and creates the draft; `technical-writing` edits prose.

## When to use it

Use it when you need a release-notes draft for a tag range. Run it manually:

```text
/release-notes <from-tag> <to-tag>
```

You must be signed in to `gh`. The skill stops if `gh auth status` fails or either tag does not exist.

## How it works

The skill gathers merged PRs between the tags and skips PRs labeled `skip-notes`.

It groups PRs by Conventional Commit type, with features, fixes, and breaking changes first. For PRs with multiple type labels, grouping uses a strict-majority rule. Ties follow label order.

Each breaking change needs a migration line. If the PR body has none, the draft marks it `TODO: migration`.

## What you get

The skill writes `RELEASE_NOTES.md` in your working tree and stops. It never publishes.
