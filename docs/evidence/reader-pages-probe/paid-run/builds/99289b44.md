# release-notes

## What it does

Drafts release notes from merged PRs between two tags. It groups PRs by Conventional Commit type, with features, fixes, and breaking changes first, and skips PRs labeled `skip-notes`.

## When to use it

Use it to gather merged PRs and draft release notes for a tag range. Invoke it manually:

```text
/release-notes <from-tag> <to-tag>
```

Use `technical-writing` to edit prose; `release-notes` gathers the PRs and drafts the notes.

## How it works

The skill requires `gh` to be signed in. It stops if `gh auth status` fails.

It resolves each tag with `git rev-list -n1 <tag>`. If either tag does not exist, it stops before drafting with the exit reason `TAG_UNRESOLVED`.

It fetches merged PRs with:

```sh
gh pr list --state merged --search "merged:<from>..<to>" --json number,title,labels,body --limit 500
```

Grouping counts type labels using a strict-majority rule. For PRs with more than one type, the group follows the majority of their labels; the code breaks ties by label order.

Every breaking change needs a migration line. If the PR body has none, the draft marks it `TODO: migration`.

## What you get

The skill writes `RELEASE_NOTES.md` in the working tree and stops. It never publishes.

It also keeps a private ledger at `$TMPDIR/release-notes/<id>/ledger.md`.
