# release-notes

## What it does

Drafts release notes from merged PRs between two tags. It gathers the PRs and creates the draft; the neighboring `technical-writing` skill edits prose.

## When to use it

Use it when you need a release-notes draft for a tag range. Run it manually:

```text
/release-notes <from-tag> <to-tag>
```

Both tags must exist, and `gh` must be signed in. It stops if `gh auth status` fails or either tag cannot be resolved. A missing tag stops drafting with `TAG_UNRESOLVED`.

## How it works

The skill gathers merged PRs between the tags and skips PRs labeled `skip-notes`.

It groups PRs by Conventional Commit type, with features, fixes, and breaking changes first. For PRs with labels naming multiple types, grouping counts the labels using a strict-majority rule. The code breaks ties by label order.

Every breaking change needs a migration line. If the PR body has none, the draft marks it `TODO: migration`.

## What you get

A `RELEASE_NOTES.md` file in the working tree, grouped by change type and marked with any missing migration guidance.

The skill stops after writing the draft. It never publishes.
