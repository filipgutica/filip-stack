# release-notes

## What it does

Drafts release notes from merged PRs between two tags, grouped by Conventional Commit type, with features, fixes, and breaking changes first.

## When to use it

Use it to gather merged PRs and draft release notes. Use `technical-writing` to edit prose.

Run it manually:

```text
/release-notes <from-tag> <to-tag>
```

You must be signed in to `gh`, and both tags must exist.

## How it works

The skill checks `gh` authentication and resolves both tags before drafting. It stops if `gh auth status` fails or either tag cannot be resolved. A missing tag produces the exit reason `TAG_UNRESOLVED`.

It gathers merged PRs between the tags, skips those labeled `skip-notes`, and groups the rest by type. For PRs with multiple type labels, grouping uses label counts and a strict-majority rule; ties are broken by label order.

Every breaking change needs a migration line. If the PR body has none, the draft marks it `TODO: migration`.

## What you get

A draft in `RELEASE_NOTES.md` in your working tree, including any migration TODOs that need attention.

The skill never publishes. It writes the file and stops.
