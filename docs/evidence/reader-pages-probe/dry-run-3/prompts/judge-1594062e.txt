# See which process held a port

portlog records which process held each local TCP port over time. Use it to answer “what was on port 3000 an hour ago?” after the process has exited.

```sh
brew install example/tap/portlog
```

macOS and Linux · Written in Go · MIT license

## Try it

Start recording, then look up port 3000:

```sh
portlog start
portlog who 3000
```

## Commands

### Record port history

`portlog start` runs a background recorder. Stop it with:

```sh
portlog stop
```

### Look up a port

`portlog who 3000` shows every process that held port 3000, newest first.

Limit the results to the last two hours:

```sh
portlog who 3000 --since 2h
```

### Free a port

Stop the process that holds port 3000 now, after confirmation:

```sh
portlog free 3000
```

Add `-y` to skip confirmation:

```sh
portlog free 3000 -y
```

## Good to know

### History retention

portlog keeps history for 7 days in `~/.portlog/`.

### Command-line arguments

portlog never records command-line arguments, because they can hold secrets.

# portlog

Know what held a port—even after the process exits.

portlog records which process held each local TCP port over time, so you can answer “what was on port 3000 an hour ago?”

## Install

```sh
brew install example/tap/portlog
```

Runs on macOS and Linux.

## Start recording

```sh
portlog start
```

Runs the recorder in the background. Stop it with:

```sh
portlog stop
```

## Look up a port

See every process that held port 3000, newest first:

```sh
portlog who 3000
```

Limit the history to the last two hours:

```sh
portlog who 3000 --since 2h
```

## Free a port

Stop the process holding port 3000 now:

```sh
portlog free 3000
```

portlog asks for confirmation first. Add `-y` to skip it.

## How it works

The recorder polls `lsof` every two seconds on macOS and reads `/proc/net/tcp` on Linux. History stays in `~/.portlog/` for seven days.

Command-line arguments are never recorded because they can hold secrets.

## About

Written in Go. MIT licensed.
