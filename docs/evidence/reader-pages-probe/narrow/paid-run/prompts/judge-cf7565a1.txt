# Renaming rooms in the Kestrel directory

## 1. Keep room identity separate from its name

Kestrel is a fictional directory of shared work rooms. Each room has a room key and a display name. These serve different purposes: the key identifies the room, while the display name is the human-readable label people see.

A room receives its key when it is created. That key never changes, and Kestrel never reuses it for another room. Room owners can change the display name. A rename therefore changes the label people see while preserving the room’s identity.

This distinction matters when building links. Saved links identify rooms by their keys. When someone opens a saved link, Kestrel looks up the key and displays the room’s current name. The link can continue to reach the same room after its owner changes the name.

A link built from a display name can stop finding the room after a rename because the name has changed. Use the room key to identify the destination and the display name to label it.

In the storage schema, the key column is called `room_ref`, and the display-name column is called `title_text`. Read those column names with their roles in mind: `room_ref` holds the room’s identity; `title_text` holds its changeable label.

## 2. Verify the rename through a saved link

To verify a rename, begin before changing the display name. Save a room link that identifies the room by its key. This gives you a link to open after the rename.

Then rename the room and open the saved link. Check both parts of the expected result:

- The link reaches the same room.
- The room shows its new display name.

These checks establish different things. Reaching the same room verifies that the saved link still identifies its destination. Seeing the new name verifies that Kestrel displays the current label when the link is opened.

Keep both checks in the verification. The expected result is the same room with its new name, reached through the link saved before the rename. That sequence directly checks the behavior that key-based links are meant to preserve when a room owner changes a display name.

# Renaming rooms in the Kestrel directory

## 1. Rename a room and check its saved link

Kestrel is a fictional directory of shared work rooms. Each room has a room key and a display name, the human-readable label people see. Room owners can change that label. When you rename a room, verify that an existing saved link still reaches it and shows the new name.

Start with a room you own:

1. Before you rename the room, save a room link that identifies it by its key.
2. Change the room’s display name.
3. Open the saved link.
4. Confirm that it reaches the same room and shows the new display name.

For an illustrative example, suppose a room’s display name changes from “Design room” to “Planning room.” Open the link saved before the change. The expected result is the same room, now displayed as “Planning room.”

Check both parts of that result. Reaching the room verifies that the saved link still identifies it. Seeing the new name verifies that Kestrel displays the renamed room correctly. A link that opens is only part of the check; the displayed name also matters.

## 2. Understand what the link identifies

Kestrel assigns a room key when it creates a room. That key never changes, and Kestrel never reuses it for another room. It provides a fixed identity throughout a room’s name changes.

A display name serves a different purpose: it labels the room for people. Because an owner can change it, the name can differ between the time someone saves a link and opens it.

Saved room links identify rooms by their keys. When someone opens one, Kestrel looks up the key and displays the room’s current name. The saved link therefore does not need the old display name to find the room.

A link built from a display name can stop finding the room after a rename because that name has changed. When building room links, use the room key.

In the storage schema, `room_ref` is the key column, and `title_text` is the display-name column. Use this mapping when reading the stored fields for a rename.
