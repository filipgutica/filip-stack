# Renaming rooms in the Kestrel directory

## 1. Identify a room by its key

Use the room key to identify a room when you build a saved link. A rename changes the room’s display name. Its key stays the same.

Kestrel is a fictional directory of shared work rooms. Each room has a room key and a display name. These values have different purposes:

- The room key identifies the room. Kestrel assigns it when the room is created. It never changes or gets reused for another room.
- The display name is the human-readable label people see. Room owners can change it.

This distinction lets a saved link continue to identify a room after its owner changes the label. When someone opens the link, Kestrel looks up the key and displays the room’s current name. The name shown when the link opens can therefore differ from the name shown when it was saved.

A link built from a display name can stop finding the room after a rename because that name has changed. Do not treat the display name as a permanent room identifier.

In the storage schema, `room_ref` is the key column and `title_text` is the display-name column. Keep these meanings clear when working with the stored values: `room_ref` identifies the room, while `title_text` supplies its human-readable label.

## 2. Verify the rename with a saved link

Check a rename with a room link saved before the change. The expected result has two parts: the link reaches the same room, and Kestrel shows the new display name.

1. Before renaming the room, save a link that identifies it by its room key.
2. Have the room owner change the display name.
3. Open the saved link.
4. Confirm that it reaches the same room.
5. Confirm that Kestrel displays the new name.

Saving the link before the rename gives you a link from the room’s earlier naming state. Opening that same link afterward checks that it still identifies the room.

Check both results separately. Reaching the same room verifies the saved link’s target. Seeing the new name verifies that Kestrel displays the current label.
