# Design language probe: second run

Date: 2026-11-04

Status: complete. This was a one-off run outside PluginBench, approved by Filip.
It repeats the [first run](probe-run-2026-11-04.md) with its flaws fixed and a larger sample.

## Result

The guidance is **not supported** under the fixed decision rule.

| Rule part | Result |
| --- | --- |
| Head no worse than base on every objective measure, per probe | Fails on the data table and the docs page. Table: page overflow 1 vs 0, phone table columns 6 vs 0. Docs: failed probe checks 5 vs 4. |
| Head better on at least one measure | Met. Head had fewer builds with off-list breakpoints in all three probes (0 vs 1, 0 vs 2, 0 vs 8), and fewer table border colors and radii. |
| Judges prefer head overall in at least 2 of 3 probes | Fails. Judges preferred base in 3 of 3 probes. Opus 5.5 alone also preferred base in 3 of 3. |

**Breakpoint change alone: the widths hold; the full pre-registered test does not.**

- **Widths.** All 24 head builds used only 640 and 800 px. 11 of 24 base builds used other widths (420, 760 or 900 px).
- **Pre-registered test.** It fails on its third clause. On the data table, head was worse on page overflow (1 vs 0) and on phone table clipping (6 vs 0). A post-hoc diagnostic below traces both to the Data views guidance, not the widths.
- **Rail wording.** The breakpoint table itself carries a regression. Its Tablet row says side navigation "becomes a drawer or a native scrolling section strip". Base says only that navigation "can become" one, and both arms' `docs.html` wraps the rail. All 8 head docs rails scroll sideways at 800 px, and all 8 base rails wrap. Several docs judges named the clipped rail.

A smaller PR could ship the two widths and the example-page changes without the scrolling-strip line. It would need its own run.

## Scoring

The rules were written before the first build: run 1's rules in `scorer/prereg.md`, plus `run-2/prereg.md`.
The run 1 Playwright scorer was extended with two measures:

| Measure | Per-build value |
| --- | --- |
| Phone table clipping (decision measure) | At 390 px, table columns whose cells are hidden, or cut off by an `overflow: hidden` ancestor or the viewport without a scrolling wrapper. A column inside a wrapper that scrolls counts as reachable. Cells that span columns are skipped. |
| Muted body text share (diagnostic) | At 1280 px light, characters of visible `<p>` text in `--text-muted` divided by those in `--text-muted` or `--text` |

Before any build, both measures ran on run 1's 18 builds and on a control page.
Muted share marked all 3 run 1 head docs builds above 0.5 and no base docs build.
Phone table clipping scored 6 on run 1's head table `f1c2c084`, 2 on a control table in an `overflow: hidden` wrapper, 1 on a control table that hides a column, and 0 on a scroll-wrapped control table.
Every failed probe check and the one page overflow were then checked by hand against the page source and screenshot.

## Notable findings

- **Head tables cut off their state messages at phone width.** This was measured after the judges named it, so it is a diagnostic, not a scored measure (`scorer/statecells.mjs`). All 8 head table builds put the loading, empty and error messages in a row that spans the columns of a wide table, as the head Data views section asks. At 390 px those messages run past the edge of the table's scroll wrapper in all 8 builds (19 cells). No base build does this: all 8 put each state in its own panel. Judges voted base on all 24 table pairs, and most named the cut-off state content.
- **Run 1's head table overflow repeated.** Head build `7b8fb2d0` let its three state tables push the page to 596 px at a 390 px viewport, the same failure as run 1's `f1c2c084`. Its PR state and Size columns are cut off by the viewport, which is the 6 on the phone table measure. No other build in either arm overflowed.
- **Head docs rails scroll, base docs rails wrap.** All 8 head docs builds turn the side rail into a horizontally scrolling strip at 800 px, as head's Tablet row says ("becomes a drawer or a native scrolling section strip"; base says navigation "can become" one). All 8 base builds wrap the links, as both arms' `docs.html` does. In a static phone screenshot the scrolling strip cuts off its last link, and several judges named that. This is an inference from the page source and the judges' reasons.
- **Muted prose is in both arms.** 7 of 8 docs builds in each arm set most prose in `--text-muted`. Both arms' `docs.html` sets `p { color: var(--text-muted) }`, so the builds copy the shared example. Run 1's split (3 of 3 head muted, 0 of 3 base) did not repeat and was likely chance.
- **Current section in the docs rail.** 4 of 8 base and 5 of 8 head docs builds mark no rail link with `aria-current`, and none uses an active class instead. This is the one-build docs regression.
- **Breakpoints.** Every head build used exactly 640 and 800 px. Base builds used 640 px everywhere, plus 760 px in all 8 docs builds (from the base `docs.html`), 760 or 900 px in 2 tables, and 420 px in 1 form.
- **Forms.** Both arms scored the same on every objective measure, and every form passed both probe checks. Judges still preferred base 20 to 3. Their reasons were tighter grouping, less repeated helper copy and consistent control heights. The run does not show which head change caused those differences.

## Validity threats

- **Judges see only the shared guidance.** `shared-guidance.md` leaves out the sections that differ, including head's Forms and Data views. Judges cannot credit head builds for following those rules, and can mark them down for it, as with the in-table state messages. That matches how a reader without the new guidance would see the pages, but it is not a test of compliance with head's own rules.
- **Correlated judges.** Astra and Sol 6.1 share a provider, and Sol 6.1 is also the builder. Opus 5.5 is the only cross-provider judge, and it agrees with the others on the direction in all 3 probes.
- **Static screenshots.** Judges cannot scroll a strip or a table, open a disclosure, or trigger the form error.
- **Post-hoc diagnostics.** The state-message count and the rail comparison were measured after the judges. They explain votes; they were not part of the decision rule.
- **File delivery.** Builders read their guidance from a file, not from the prompt. The global Codex instructions still name `~/design-language/DESIGN.md`, but no build read it.
- **Standalone only.** The library-stack build did not run, so this run says nothing about pages built on `@filipgutica/ui`.
