## Scoring

The scoring rules were written before the first build started.
A Playwright 1.62.1 Chromium script, adapted from the audit's `verify.tmpl.js`, scored each page.
It served the pages over `http://127.0.0.1` and opened each one in a fresh browser context at 390, 720 and 1280 px, in light and dark.
Every per-probe value is the sum over the three attempts. Lower is better.

| Measure | Per-build value |
| --- | --- |
| Undefined vars | Distinct `var(--x)` names with no computed value on `:root` |
| Contrast failures | Distinct visible text elements below 4.5:1, or 3:1 for large text, at any of the 6 loads |
| Overflow widths | Widths where `scrollWidth > clientWidth` in either theme |
| Forced-colors stops without outline | Tab stops with outline style `none` or width 0 under `forcedColors: 'active'`, at any width |
| Builds with off-list breakpoints | 1 when the page's viewport `@media` widths are not a subset of {640, 800}, within 1.5 px. `tokens.css` is excluded. |
| Border colors, border radii | Distinct computed values on visible elements at 1280 px light |
| Failed probe checks | Form: one filled Save button; a visible inline error after clearing the name and pressing Save. Table: visible loading, empty and error states; Size column right-aligned. Docs: exactly one rail link with `aria-current`. |

Two checks guard the scorer.
A control page with known defects scored as expected: low contrast, an undefined variable, overflow, a 700 px breakpoint, and links without an outline.
Every failed probe check and the one overflow were then checked by hand against the page.
The first scoring pass ended the Tab walk at the first repeated link target, so it missed stops on pages with two links to one section. The fix ends the walk only when focus returns to a stop it has already seen. All 18 builds were then scored again. No reported measure changed: forced-colors failures were 0 in both passes.

## Blind judges

Judges are diagnostics, not the score.
Each pair bundle held `A/` and `B/` screenshots, at 1280 px light and 390 px dark, in random order, plus a neutral `criteria.md`.
The criteria named DESIGN.md consistency and library-docs consistency. No bundle included either arm's DESIGN.md or the library docs.
The judges were Astra (`gpt-6-astra`), Sol 6.1 (`gpt-6.1-sol`), and Opus 5.5 (`claude-opus-5-5`), each at high effort.
Astra and Sol 6.1 share a provider, so their votes are not independent. Sol 6.1 is also the builder model.
All 27 judges listed no unread files, so all 27 votes count.

## Notable failures

- **Head table overflow.** Head build `f1c2c084` put its loading, empty and error tables outside a scroll wrapper. At 390 px the page is 636 px wide. Three judges also saw it.
- **Phone tables in both arms.** Several judges saw phone tables cut off the PR state and Size columns, either clipped inside a frame or hidden. The overflow measure counts only page scroll, so it does not see this.
- **Docs current section, both arms.** None of the 6 docs builds marks the current rail link. None uses `aria-current` or an active class. Both arms failed this check 3 of 3.
- **Docs prose color.** All 3 head docs builds set every prose paragraph in `--text-muted`. All 3 base builds used `--text` for prose and kept `--text-muted` for the lede. This was measured after the judges named it, so it is a diagnostic, not a scored measure. It explains most docs votes. The muted text still passes 4.5:1, so the contrast measure does not count it. The run does not show which head change caused it.
- **Base breakpoints.** All 3 base docs builds used 760 px, from the base `docs.html` example. One base form (`6004cbf4`) used 420 px, which appears in neither arm nor the host copy.
- **Probe checks otherwise passed.** All 6 forms had one filled Save button and showed "Enter a project name" after an empty submit. All 6 tables showed the three states and right-aligned Size.

## Validity threats

- **Host guidance outside the arm.** The global Codex instructions tell agents to read `~/design-language/DESIGN.md`. That copy matches neither arm. Two base builds read it: `6004cbf4` (form) and `773b2ca5` (table). No head build did. No build read this repository's `host-config/`. Dropping both builds does not change the verdict, because the judges' 0 of 3 fails the rule on its own.
- **Shared host skills.** Builders also read the global `frontend-design` and `ux-laws` skills. These were the same in both arms.
- **Small sample.** There were 3 attempts for each arm and probe. One build decided each objective regression on the table.
- **Judges without references.** Judges rated consistency from screenshots alone, without DESIGN.md or the library docs. Base builds may simply look more polished.
- **Scorer limits.** Variables scoped to a component count as undefined in both arms. Contrast ignores images and gradients. Forced colors was emulated in Chromium only. Screenshots do not show the empty-name error state.
- **Standalone only.** The library-stack build did not run, so this run says nothing about pages built on `@filipgutica/ui`.
